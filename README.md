# @kep4yk/rbac-jwt-core

## Назначение модуля
`@kep4yk/rbac-jwt-core` — это масштабируемое ядро системы управления доступом (Role-Based Access Control — RBAC) на основе JWT-токенов. Модуль спроектирован для интеграции в микросервисную архитектуру научного портала. 

Пакет инкапсулирует в себе всю сложную логику: от генерации и криптографической валидации токенов до синхронизации прав доступа между реляционной базой данных и быстрым in-memory кэшем.

## Используемый стек технологий
* **Язык разработки:** TypeScript / Node.js
* **База данных:** Microsoft SQL Server (надежное хранение схемы ролей, пользователей и их связей).
* **Кэширование и сессии:** Redis (хранение матрицы доступности для снижения нагрузки на БД, а также реализация механизма `blacklist` для отзыва токенов).
* **Аутентификация:** JSON Web Tokens (JWT).
* **Лицензия:** GNU AGPL v3.0

## Архитектура
Пакет спроектирован по слоистой архитектуре для удобства тестирования и поддержки:
1. **Слой данных (Data Layer):** Модуль взаимодействия с SQL Server (управление пулом соединений, CRUD-операции для ролей).
2. **Слой кэширования (Cache Layer):** Интеграция с Redis для моментальной сверки прав и обработки отозванных токенов.
3. **Ядро RBAC (Core / JWT):** Бизнес-логика выпуска токенов, парсинга claims и принятия решений о допуске.
4. **Публичный API (API Layer):** Набор экспортируемых middleware и вспомогательных функций для легкого встраивания защиты в любые маршруты консьюмера (сервера, использующего данный пакет).# RBAC JWT Access Control

## Назначение модуля
Данный npm-пакет предоставляет готовое ядро системы управления доступом (RBAC) на основе JWT-токенов. Разработан специально для интеграции в микросервисную архитектуру научного портала. Модуль инкапсулирует логику генерации и валидации токенов, проверку прав доступа и работу с хранилищами данных.

## Используемый стек технологий
* **Язык разработки:** TypeScript / Node.js
* **База данных:** Microsoft SQL Server (для хранения схемы ролей, прав пользователей и представлений)
* **Кэширование:** Redis (для in-memory хранения матрицы доступности и реализации механизма отзыва токенов / blacklist)
* **Безопасность:** JSON Web Tokens (JWT)
* **Тестирование и CI/CD:** Jest/Vitest, GitHub Actions (планируется)

## Архитектура
Модуль поставляется как подключаемая библиотека (middleware/helpers), которая встраивается в любой Express/Fastify сервер. 
1. **Слой данных:** Взаимодействует с SQL Server для базовых CRUD-операций с ролями.
2. **Слой кэширования:** При старте или обновлении прав матрица доступа выгружается в Redis для минимизации обращений к БД при каждом запросе.
3. **Слой авторизации:** Парсинг JWT (извлечение claims), сверка с кэшем Redis и выдача вердикта о допуске к ресурсу.
